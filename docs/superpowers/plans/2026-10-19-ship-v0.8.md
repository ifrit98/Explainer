# Ship v0.8.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release v0.8.0 with the artifact eval, its dev results and an honest account of what it found, and fix the doc drift without touching measured skill text.

**Architecture:**
- Mostly docs and release mechanics. The only code change is one repo-integrity test that guards AGENTS.md.
- Work happens on branch `release/v0.8.0`. It lands on `main` as one squash commit, which matches the repo's one-commit-per-version history (`v0.7.0: …`). The tag and the GitHub release are cut from that commit.

**Tech Stack:** Python 3 / uv, pytest, the `explainer` CLI, git, GitHub CLI (`gh`).

**Spec:** `docs/prds/PRD-001-ship-v0.8.md`

## Global Constraints

- Version `0.8.0` everywhere:
  - `pyproject.toml` (`version = "0.8.0"`)
  - `plugin/.claude-plugin/plugin.json` (`"version": "0.8.0"`)
  - the pin in `plugin/bin/explainer` (`@v0.8.0`)
- **Measured text must not change.** `git diff --stat main -- plugin/skills explainers` must be empty at every commit.
- **The repo is public.** Nothing in `docs/prds/`, `docs/superpowers/` or `evals/artifact/` may carry personal or private-project context, absolute home paths, emails or keys.
- **The release notes state the negative result.** They must not read as a success story for the skill tiers.
- **Release style:**
  - annotated tag `v0.8.0` with message `v0.8.0: measure the toolkit, not the examples`;
  - GitHub release titled `v0.8.0 — Measure the toolkit, not the examples`.

## Review Focus

1. **Private data in the committed eval output.** `evals/artifact/results/*/work/` holds raw agent transcripts and review runs. Someone browsing the public repo would expect no home paths, emails or keys. A scan in Task 3, Step 1 pins this.
2. **A plugin pin that points at a tag that doesn't exist yet.** `plugin/bin/explainer` installs from `@v0.8.0`, so a user installing between the merge and the tag push gets a failure.
   - Task 4 pushes the tag immediately after the merge.
   - It then verifies the tag with `git ls-remote`.
3. **New Markdown files with broken relative links:** AGENTS.md, the PRDs, this plan and the eval reports. `test_relative_links_resolve` covers them all. Task 3, Step 4 runs the full suite with the new files in place.
4. **Measured text changed by accident**, for instance a sweeping find-and-replace of "seven". The `git diff --stat main -- plugin/skills explainers` check runs in Tasks 2 and 3.
5. **Mermaid rendering is checked only in CI.** Locally, `explainer check` runs without `--diagrams` because the Mermaid CLI comes through `npx`. Task 4 waits for a green CI, which runs `explainer check --diagrams`.

- [ ] **Step 4: Publish the GitHub release**

Run: `gh release create v0.8.0 --title "v0.8.0 — Measure the toolkit, not the examples" --notes-file <notes>`

The notes need three parts.

**1. A one-line summary**, then the changelog bullets.

**2. "What it found"**, with these facts and figures copied from `docs/evals.md`:
- **The quiz is at its ceiling.** Every condition scores 94–100% with a strong reader and with Haiku, so it cannot rank the conditions.
- **The principles carry the measurable value.** They cut length 40% (1,689 → 1,006 words), came first in effort rank in all three grading passes, and cost the least ($0.21 per build).
- **The quick tier** is the shortest at 606 words, ranks below the principles, and makes the most factual errors (6–9).
- **The published tier** costs 13 times as much as the principles ($2.81) and takes 11.8 minutes, for no measured gain.
- **This is a 10-subject dev run.** The effort ranking is a model's and is noisy; a person's ranking has to confirm it.

**3. The first run was invalid**, for two reasons: builders loaded the repo's CLAUDE.md in every condition, and the grader read Markdown with inline code stripped. Both are fixed.

Link `docs/evals.md#what-the-artifact-eval-found`. End with the Upgrade line, as v0.6.0 and v0.7.0 do:

> **Upgrade:** plugin users get v0.8.0 on the next `/plugin` update; the `explainer` wrapper now pins `@v0.8.0`. `explainer eval artifact` needs the `claude` CLI.

Use the corrected figures: quick's errors are 4–9, and the published tier has no *consistent* measured gain. Its errors (1–2) overlap the principles' (1–4).

Expected: `gh release view v0.8.0` shows the title and notes.
